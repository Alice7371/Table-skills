# Optional delegated execution

Ordinary use stays with the current executor and deferred collection. Do not
create a child or intermediate coordinator as part of the default path.

Only when the user explicitly requests an isolated executor, pass the standalone
task and job path without parent history. Verify the child's own supported tools.
It follows the same runtime contract: send once, persist the Chat binding, and
return the pending link. It does not keep a parent/child polling loop alive or
delegate again. Model/effort selection needs the user's existing authorization.

Whether this saves cost is unverified for the revised flow. Include dispatch,
child initialization, parent re-entry, collection and acceptance in any requested
comparison. Old isolated-trial budget gates and worker files are historical test
artifacts, not prerequisites for ordinary use.
