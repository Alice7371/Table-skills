# 项目交接

让下一次对话拿到正确的成果、有效决定和明确的第一步，在已授权范围内继续，避免用户重述和两个对话同时修改。适用于代码、文档、研究和媒体制作。

## 入口

- **压缩计数提示**：收到宿主提供的真实计数或待提醒提示时，读 [自动压缩计数与提醒回执](references/compaction-reminder.md)。前两次不因次数提醒，第三次后在最近一次进度汇报提醒一次；该入口不再要求下表三项同时满足。
- **工作节点检查**：准备汇报一个可独立验收的阶段结果、进入下一大段工作，或发现目标／版本／约束混淆时，按下节做一次判断。这些节点可以来自 Agent 完成的验证、发现的事实和任务进展，不要求用户说出关键词。普通小步骤和纯问答不逐回合检查。
- **仅保存**：明确要求保存进度、仅整理交接，或仅输入 `$project-handoff` 时，读 [保存、自动接续与恢复](references/handoff.md)，执行“保存”；笼统的“交接一下”不自行扩展为新建任务。
- **完整交接**：用户明确要求新建并继续，或确认了已说明“保存材料、在指定目录新建并打开对话、核对后继续”的提议时，读同一附页，执行“保存 → 自动接续”。已取得的这次完整授权不逐步重问。
- **恢复／查看**：指定交接来源并要求继续时执行“恢复”；只要求查看时只读。
- 对本技能的讨论、审查、修改或批准修改，不是执行当前任务交接的授权。

## 检查与提醒分开

| 检查项 | 提醒所需依据 |
| --- | --- |
| 可接手的位置 | 当前操作已安全收拢，成果和必要验证可定位；应由用户验收的阶段不能由 Agent 自称验收通过。运行中的任务能说明状态、查询入口和归属，不因换对话重复执行。 |
| 明确的后续工作 | 目标、范围、下一步及完成标准已清楚，新对话能确定第一步。项目已结束且没有后续工作时，只按用户要求保存，不主动新建。 |
| 具体的切换收益 | 能结合本次事实说明切换的好处，例如已结束的大量探索与后续执行可以分开，或已纠正的版本混淆有明确替代关系、带入旧路线会干扰下一步。不能只说“上下文太长”或“换个对话更清爽”。 |

普通工作节点三项均有依据时建议交接；次数提醒按专门入口执行。新的已核实混淆先纠正，再在安全位置提前提醒，不受次数冷却限制，不必等同一错误发生两次。关键缺项仍未解决时，先解决缺项，不把换任务当成修复。

- 有混淆时先按用户最新决定与权威资料纠正；关键目标、版本或授权仍不清楚时，先解决缺项。换对话不用于绕过阻塞、失败原因或待验收步骤。
- 判断依据是用户决定、验证结果、真实文件／任务状态和宿主压缩事件，不是 Agent 回答中出现“已完成”“下一阶段”等字样。普通工具报错、用户正常改需求、对话变长不单独构成提醒理由；第 1、2 次自动压缩不因次数提醒。
- 仅记录不充分时，在已有授权覆盖的状态更新中补齐；不因此直接建议换对话。不为检查扫描完整私人历史或额外调用模型。

在当前操作安全结束后，用简短提示说明具体原因、接续第一步和确认覆盖的动作。例如：“本阶段已按约定验收，后续将依据定稿实施；前面的多轮方案已废弃，适合在这里交接。确认后我会保存材料，在同一项目的原目录新建并打开对话，核对后继续 X。”等待交接决定期间，继续当前已授权工作；未经确认不执行交接。提醒本身不授权写文件、停止任务或新建对话。若没有自动新建能力，提示应改为实际可做的保存和手动入口，不许诺自动接续。

## 去重与压缩

- 同一任务、同一具体问题只提醒一次。次数提醒后至少冷却 3 次新增自动压缩；用户回应继续后，从回应时的计数起至少再冷却 3 次。用户未回应或要求继续时，继续已授权工作。
- 冷却期间只因新的可核实混淆或符合表中依据的新阶段提前提醒；时间经过、换一种说法不算新原因。达到下一次数提醒点时按计数入口执行。
- 用户说“本对话不提醒”后，本对话停止主动提醒；显式交接请求仍执行。
- 有计数器时按附页登记已发出的提醒、实际回应和静默范围；没有计数器时沿用已有任务状态。恢复后继承冷却与静默；无法核实历史时不虚构次数或已提醒记录。宿主已给出可靠待提醒状态时，不因聊天摘要缺少历史而静默漏报。
- 不按上下文百分比、对话轮数或模型感觉估算次数，不预测压缩时点，不修改自动压缩设置。次数是提醒初值，不是已经发生错误的证明。

本技能由 Agent 在工作回合内执行；配套 Codex Hook 负责持久计数和向下一轮注入提醒状态，不在回答发出后扫描文字。实际混淆识别仍由 Agent 判断，不能承诺零漏报。配套 Hook 必须经过宿主原生信任并实际验证，不能凭磁盘文件宣称已生效。规则保留在本技能及其配套资源中，不写入 AGENTS.md、CLAUDE.md，不添加定时任务。对本技能的讨论或批准修改不触发当前任务交接。
