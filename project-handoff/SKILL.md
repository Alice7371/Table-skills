# 项目交接

让下一次对话拿到正确的成果、有效决定和明确的第一步，在已授权范围内继续，避免用户重述和两个对话同时修改。适用于代码、文档、研究和媒体制作。

## 入口

- **压缩计数提示**：收到宿主提供的真实计数或待提醒提示时，读 [自动压缩计数与提醒回执](references/compaction-reminder.md)。前两次不因次数提醒；首次到第三次后，在当前操作安全收拢、仍有明确后续时提醒，不另等大阶段。之后次数只解除冷却，不自动产生新提醒。
- **工作节点检查**：准备汇报一个可独立验收的阶段结果、进入下一大段工作，或发现目标／版本／约束混淆时，按下节做一次判断。这些节点可以来自 Agent 完成的验证、发现的事实和任务进展，不要求用户说出关键词。普通小步骤和纯问答不逐回合检查。
- **仅保存**：明确要求保存进度、仅整理交接，或仅输入 `$project-handoff` 时，读 [保存、自动接续与恢复](references/handoff.md)，执行“保存”；笼统的“交接一下”不自行扩展为新建任务。
- **完整交接**：用户明确要求新建并继续，或确认了已说明“保存材料、在指定目录新建并打开对话、核对后继续”的提议时，读同一附页，执行“保存 → 自动接续”。已取得的这次完整授权不逐步重问。
- **恢复／查看**：指定交接来源并要求继续时执行“恢复”；只要求查看时只读。
- 对本技能的讨论、审查、修改或批准修改，不是执行当前任务交接的授权。

## 检查与提醒分开

| 检查项 | 提醒所需依据 |
| --- | --- |
| 可接手的位置 | 当前操作已安全收拢，成果和必要验证可定位；应由用户验收的阶段不能由 Agent 自称验收通过。运行中的任务能说明状态、查询入口和归属，不因换对话重复执行。 |
| 明确的后续工作 | 目标、范围、下一步及完成标准已清楚，新对话能确定第一步。项目已结束且没有后续工作时，只按用户要求保存，不主动新建。 |
| 具体的切换收益 | 能结合本次事实说明切换的好处，例如已结束的大量探索与后续执行可以分开，或已纠正的版本混淆有明确替代关系、带入旧路线会干扰下一步。不能只说“上下文太长”或“换个对话更清爽”。 |

普通工作节点三项均有依据时评估交接，并遵守下文去重与冷却；首次次数提醒只要求安全位置和明确后续。新的已核实混淆先纠正，再在安全位置提前提醒，不受次数冷却限制；任务静默仍优先。关键缺项仍未解决时，先解决缺项，不把换任务当成修复。

- 有混淆时先按用户最新决定与权威资料纠正；关键目标、版本或授权仍不清楚时，先解决缺项。换对话不用于绕过阻塞、失败原因或待验收步骤。
- 判断依据是用户决定、验证结果、真实文件／任务状态和宿主压缩事件，不是 Agent 回答中出现“已完成”“下一阶段”等字样。普通工具报错、用户正常改需求、对话变长不单独构成提醒理由；第 1、2 次自动压缩不因次数提醒。
- 仅记录不充分时，在已有授权覆盖的状态更新中补齐；不因此直接建议换对话。不为检查扫描完整私人历史或额外调用模型。

## 最终答复中的提醒

本轮决定提醒且用户尚未回应时，最终答复末尾必须保留一段“交接建议：”，说明本次原因、接续第一步和确认覆盖的动作。例如：“交接建议：设计已确认，后续进入带配音样片，适合在这里收拢旧方案。确认后我会保存材料，在同一项目原目录新建并打开任务，核对后继续制作样片。”未获用户验收的成果不能写成“已确认”。

进度消息可以先简短提醒，但不能代替最终答复中的建议；两处展示是同一次提醒，不重复计数。用户本轮已回应、建议已撤销或本任务没有后续时，不再保留待决定建议。已经在最终答复交付过的建议，不挂在以后每一轮末尾。

有计数器时，提醒前按附页 `prepare` 登记本轮建议；只有实际展示后才登记相应渠道。Stop 仅核对本轮已准备的建议，漏写最多补一次。没有 Hook 或任务标识时，由 Agent 在最终答复前自检，并在已有任务状态保留回应和去重依据。

等待交接决定期间继续已授权工作，未经确认不执行交接。提醒不授权保存业务交接材料、停止工作或新建任务；计数器回执只用于本 Skill 的提醒状态。若没有自动新建能力，提示应改为实际可做的保存和手动入口，不许诺自动接续。

## 去重与压缩

- 同一实质阶段、同一具体问题只提醒一次。设计转样片、样片转完整版、开场转正文可评估；同一段的改版本、调参数、重渲染不是新阶段。阶段和次数同时触发只发一条。
- 一次提醒之后，普通再提醒必须同时满足：新的实质阶段、有具体切换收益、已新增至少 3 次自动压缩。用户明确回应“先不交接／继续做”后，从回应时计数起至少再冷却 3 次；同一回应重复读取不能延长冷却。未回应或直接布置后续工作不追问，继续已授权工作。
- “做完 X 再提醒”以用户指定节点为准，到节点评估一次，不附加次数门槛；节点未到时普通阶段与次数都不催促。新的已核实混淆可以提前提醒，同一问题去重。
- “本任务不提醒”关闭本任务所有主动提醒，直到用户主动恢复；显式交接请求仍执行。普通工作指令里的“继续”不自动解释为回应交接，更不解释为批准交接。
- 有计数器时按附页记录阶段、建议、展示渠道、实际回应和静默范围，恢复后继承。自动压缩次数、实际提醒次数、提醒发生时的压缩序号分别报告；旧状态未记录提醒总数时写“历史未知”，不能用压缩序号填总数。
- 不按上下文百分比、对话轮数或模型感觉估算次数，不预测压缩时点，不修改自动压缩设置。次数是提醒初值，不是已经发生错误的证明。

本技能由 Agent 在工作回合内执行；Codex Hook 负责计数、注入和本轮最终提醒核对，不扫描私人历史或自行判断业务阶段。实际阶段、切换收益和混淆仍由 Agent 判断，不能承诺零漏报。配套 Hook 必须经过宿主原生信任并实际验证，不能凭磁盘文件宣称已生效。规则只保留在本技能及配套资源中，不写入 AGENTS.md、CLAUDE.md，不添加定时任务。讨论或批准修改本技能不触发当前任务交接。
