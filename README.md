# 🧰 Table Skills

把日常使用中跑通的 AI 技能整理在这里。第一版先收录两个：让长任务更容易接着做的「项目交接」，以及把独立重任务交给网页 ChatGPT 的「网页替身」。后续根据实际使用继续调整。

这些技能以 `SKILL.md` 为入口。**当前主要面向 Codex 桌面端；网页替身的完整运行路径在 Windows + Chrome 上验证过。** 安装技能不会自动提供缺失的浏览器接口、Chat 读取接口或 Hook 权限。

---

## 📋 目录

| 技能 | 一句话 | 使用入口 |
|---|---|---|
| 🔄 [project-handoff（项目交接）](project-handoff/) | 保存有效进度和决定，让下一次对话能接着做 | [SKILL.md](project-handoff/SKILL.md) |
| 🌐 [web-stand-in（网页替身）](web-stand-in/) | 把不依赖当前上下文的重任务交给网页 ChatGPT，完成后取回原文 | [SKILL.md](web-stand-in/SKILL.md) |

## 📦 安装方式

把需要的技能链接发给支持安装 Skills 的 Agent，例如：

```text
帮我安装项目交接技能：https://github.com/duoduoler-ops/Table-skills/tree/main/project-handoff
```

```text
帮我安装网页替身技能：https://github.com/duoduoler-ops/Table-skills/tree/main/web-stand-in
```

让 Agent 先检查当前宿主是否具备技能要求的工具，再安装到宿主发现的 Skills 目录。请保留整个技能文件夹，附带的 `references/`、`scripts/` 和 `agents/` 都有用途；只复制 `SKILL.md` 不能替代脚本和运行接口。

如果此前使用旧名 `web-offload`，迁移时先备份旧目录，再替换为 `web-stand-in`，避免两个名称同时自动触发。已派发任务保留原 `job.json` 和原技能目录，完成取回后再迁移；不要改旧任务身份或重发。

## ✨ Skills

### 🔄 project-handoff（项目交接）

长任务做了一半，换个对话常常要重新说明：哪个文件是定稿、哪些方案已经否决、现在该做哪一步。这个技能把真正影响接续的信息保存下来，让接手的对话先核对，再继续。

**它会做什么**

- 保存目标、有效决定、关键文件、真实进度和下一步，避免整段复制聊天记录。
- 用户只要求保存时，交付交接材料和可复制的开场白。
- 用户明确同意新建并继续时，在宿主能力允许的情况下保存、新建、核验接手，再继续已授权工作。
- 遇到阶段切换或已核实的版本混淆时，判断是否值得提醒交接。
- 配置并信任可选的 Windows Codex Hook 后，从实际观察到的第三次自动压缩开始提醒，支持冷却和本任务静默。

**怎么用**

```text
用项目交接保存当前进度，先不要新建任务。

整理交接材料，在同一项目目录新建任务并继续下一步。

读取这个项目的 PROJECT_STATE.md，核对后继续未完成工作。

本任务不再主动提醒交接。
```

**边界**：普通“继续”不等于同意新建任务；提醒也不会自动停止当前工作。没有真实压缩事件时，不猜压缩次数；没有新建任务能力时，提供手动接续入口。

可选计数器仅在 Windows 验证，安装技能不等于启用 Hook。配置前必须替换示例路径、合并已有 Hook，并完成宿主原生信任流程。见 [计数器说明](project-handoff/references/compaction-reminder.md) 和 [Hook 模板](project-handoff/hooks/codex-hooks.example.json)。

### 🌐 web-stand-in（网页替身）

有些活不需要当前项目上下文，例如查一份详细的官方资料、比较几款工具、汇总社区实测。网页替身会把这种可以独立完成的重任务发给普通 ChatGPT Chat，再把结果保存回来。

英文名 **Web Stand-in**，意思是“在网页端代你完成这部分工作的替身”；技能标识为 `web-stand-in`。

**第一版怎么运行**

1. 只准备任务问题、资料范围和交付要求，不搬运整段聊天，也不先在本地研究一遍答案。
2. 通过受支持的 Chrome 控制接口新建自己的 Chat 标签页，保留用户已有页面。默认沿用 GPT-5.6 Sol / 极高；模型不可用时说明差异。
3. 发送一次并保存 Chat 地址。长任务默认延后取回，期间不反复轮询。
4. 用户说“取回”后，通过官方 Chat 读取接口取回同一任务，保存完整原文、正文和接收凭据。
5. 直接交付文件与网页已有的简短摘要。日常使用不在 Codex 重做来源核查、内容评分或改写；需要复核时由用户另行提出。

**适合**：独立资料研究、较复杂的横向对比、独立长文分析与批评，且结果能够替代一段实质性的本地工作。

**不适合**：一句话就能回答的小问题、必须反复读取本地代码的实现任务、依赖大量当前上下文的持续修改。图片生成和完整附件下载尚未纳入第一版已验证路径。

```text
用网页替身调研这三款工具的官方说明和社区实测，给我一份完整 Markdown 报告。

这份独立长文交给网页替身分析，完成后保存原文。

取回。
```

**自动触发**：宿主允许自动选用技能时，Agent 会在任务开始、尚未展开本地研究前，判断是否属于值得委派的独立重任务；不会把所有联网问题都转出去。也可以明确使用 `$web-stand-in`。

**使用条件**：当前实现需要 Windows、PowerShell 7、Node.js、受支持的 Chrome 控制接口，以及能够读取同一 Chat 的 Codex 官方接口。Chrome 中已有的 ChatGPT 登录态需要由用户准备；只打开网页、只安装技能或只存在脚本，都不能证明整条链路可用。其他宿主暂未验证。

**用量与长度**：有机会减少 Codex 侧工作量，但浏览器协调、上下文读取和取回仍有开销，网页端也使用自己的额度。不保证固定节省比例。默认总答复上限为 10,000 字符，这是第一版接收路径的工作范围，不是模型长度上限；更长内容需另行确认完整文件交付方式。

发送状态不明时先检查原任务，不能盲目重发。网页还没完成就保留等待状态；取回失败不会自动发起另一轮研究。详细接口与恢复规则见 [运行说明](web-stand-in/references/runtime-contract.md)。

## 🛠️ 版本与反馈

当前为第一版使用基线：先在真实使用中发现问题，再做针对性调整。报告问题时，说明宿主、系统、出问题的环节和脱敏后的报错即可；不需要公开聊天正文或账号信息。

本地维护检查（Windows，使用已有 Node.js 和 Python 3）：

```powershell
node tests/web-stand-in.cjs
python -B -X utf8 tests/test_project_handoff.py
```

测试在 `.test-output/` 中生成独立样本，不连接真实 Chat，也不修改已安装的 Hook 状态。第一版发布前已通过 22 项网页收发检查、12 项计数器检查及两个技能的格式校验。
